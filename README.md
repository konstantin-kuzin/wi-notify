# WI Notify

Chrome-расширение для Azure DevOps, которое показывает Work Items, назначенные текущему пользователю.

## Что умеет

- Показывает назначенные вам WI в popup.
- Фильтрует список по категориям состояния: `All`, `Active`, `Proposed`, `Resolved`.
- Показывает бейдж со счётчиком на иконке расширения.
- Обновляет данные автоматически по настраиваемому интервалу и вручную.
- Позволяет менять статус Work Item прямо из popup.
- Показывает и добавляет комментарии Work Item прямо из popup.
- Позволяет списывать время в TimeSheet прямо из popup.
- Выполняет поиск среди всех назначенных вам задач по полям:
  - `title`
  - `description`
  - `id`
- На странице work item в Azure DevOps добавляет кнопку **Design Review Task**: создаёт связанную задачу на ревью по шаблону, проставляет связи и открывает её в новой вкладке.

## Установка (локально)

### Через Git

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/konstantin-kuzin/wi-notify.git
   cd wi-notify
   ```
2. Откройте в Chrome страницу `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение**.
5. Выберите папку проекта (где лежит `manifest.json`).

### Без Git

1. Откройте репозиторий: [github.com/konstantin-kuzin/wi-notify](https://github.com/konstantin-kuzin/wi-notify).
2. Нажмите зелёную кнопку **Code** → **Download ZIP**.
3. Распакуйте архив в удобную папку (например `~/wi-notify`). Внутри должна лежать папка с `manifest.json` — именно её и нужно выбирать на шаге 6.
4. Откройте в Chrome страницу `chrome://extensions`.
5. Включите **Режим разработчика**.
6. Нажмите **Загрузить распакованное расширение**.
7. Укажите папку, в которой лежит `manifest.json` (не родительскую папку с одним только архивом).

После изменения файлов нажимайте кнопку обновления (🔄) на карточке расширения в `chrome://extensions`.

## Обновление без потери данных

Настройки (`adoConfig`) и состояние списка хранятся в `chrome.storage.local` профиля Chrome. Они сохраняются, пока расширение **не удалено** и обновляется **та же** установленная копия (тот же ID в `chrome://extensions`).

### Как обновить правильно

1. Скачайте новую версию (ZIP без Git или `git pull` в той же папке).
2. Замените файлы **в той же папке**, из которой расширение уже загружено.  
   Если скачали ZIP — распакуйте поверх существующей папки или скопируйте содержимое новой версии в старую папку с заменой файлов.
3. Откройте `chrome://extensions`.
4. На карточке **WI Notify** нажмите **Обновить** (🔄).

Настройки коллекции, проекта, итерации, периода обновления, блока «Задача на ревью» и остальные данные расширения останутся.

### Чего делать не нужно

- Не нажимайте **Удалить** на карточке расширения — вместе с расширением сотрутся настройки и кэш списка.
- Не загружайте новую копию через «Загрузить распакованное» из **другой** папки параллельно со старой — это будет второе расширение с пустыми настройками. Сначала обновите файлы в прежней папке и нажмите 🔄, либо удалите старую карточку только если готовы настроить всё заново.
- Не переименовывайте и не переносите папку расширения без необходимости: Chrome привязан к исходному пути. Если папку всё же перенесли — заново укажите путь через «Загрузить распакованное» только после удаления старой карточки (настройки при удалении пропадут) либо оставьте путь прежним и копируйте файлы туда.

## Настройка

Откройте **Настройки** из popup или через карточку расширения в Chrome.

Поля:

- **Коллекция** (`apiRoot`)
  - On-prem/TFS: `https://<server>/tfs/<collection>`
  - Cloud: `https://dev.azure.com/<org>`
- **Проект** (`project`) — имя Team Project.
- **Iteration Path** (`iterationPath`) — фильтр для основного списка WI в popup.
  - `All` = без фильтра итерации.
- **Период обновления** (`refreshIntervalMinutes`) — интервал автообновления в минутах.
  - По умолчанию: `10`.

### Задача на ревью

В блоке **Задача на ревью** на странице настроек:

- **Название продукта** — если заполнено, добавляется в заголовок создаваемой задачи в квадратных скобках: `[Продукт] …`. Пустое поле — заголовок копируется из исходной задачи без префикса.
- **Дизайн-лид** — поиск пользователя; если выбран, задача на ревью назначается на него. Очистите поле, чтобы не назначать исполнителя.

Нажмите **Сохранить настройки ревью**. Остальные параметры сценария (тип задачи, шаблон, родительская задача) заданы в расширении и в UI не выводятся.

### Авторизация

По умолчанию используется `session` (cookie текущей сессии браузера в ADO).  
Параметры `apiVersion`, `authMode`, `pat` задаются в конфиге (`ado-config.mjs`/storage) при необходимости.

## Создание задачи на ревью (Design Review Task)

Кнопка появляется в форме **уже сохранённой** work item в Azure DevOps (нужен номер задачи в URL). На форме создания новой задачи без id кнопка не показывается.

### Как пользоваться

1. Откройте задачу на дизайн в Azure DevOps.
2. (Опционально) Скопируйте в буфер обмена ссылку на макеты с сайта Pixso (`pixso.net`) — расширение подставит её в раздел «Макеты» описания задачи на ревью.
3. Нажмите **Design Review Task** в панели формы (рядом с Save / в тулбаре).
4. Дождитесь создания: подпись кнопки станет «Создаём…», повторные нажатия блокируются.
5. Созданная задача на ревью откроется в новой вкладке. Исходная задача останется открытой.
6. Сообщение на странице подтвердит успех или предупредит, если не все связи удалось добавить.

### Что будет создано

- Новая задача типа **Review** в том же проекте, заполненная по командному шаблону.
- Заголовок — из исходной задачи (с префиксом продукта, если он задан в настройках).
- В описании — блок «Продуктовая задача» со ссылкой на исходную задачу; при наличии ссылки Pixso в буфере — ссылка в разделе «Макеты».
- Связь **Related** с исходной задачей.
- Привязка как **child** к родительской задаче, заданной в конфигурации расширения.
- Назначение на дизайн-лида, если он выбран в настройках.

### Ограничения

- Нужна сохранённая задача с номером; без id сценарий не запускается.
- Если задача на ревью создана, а какая-то связь не добавилась, задача **не удаляется** — донастройте связи вручную по тексту предупреждения.
- Для чтения ссылки Pixso из буфера расширению нужно разрешение на доступ к буферу обмена.

Подробности реализации — в [`docs/documentation.md`](docs/documentation.md).

## Как работает поиск

- Пользователь вводит текст в поле поиска и нажимает `Enter`.
- Popup отправляет запрос в background.
- Background выполняет WIQL-поиск по назначенным `@Me`:
  - без фильтра по `IterationPath`;
  - с учётом всех статусов;
  - `Contains` по `System.Title` и `System.Description`;
  - точное совпадение по `System.Id`, если введён числовой ID.
- Затем загружаются карточки WI и отображаются в popup.
- Кнопка `×` очищает поле поиска, результаты и возвращает UI к базовому состоянию.

## Изменение статуса Work Item

- В popup статус Work Item отображается как кликабельный бейдж на карточке.
- По клику popup запрашивает у Azure DevOps допустимые статусы для типа текущего Work Item.
- Выбранный статус сохраняется через PATCH в поле `System.State`.
- После успеха карточка сразу обновляется в UI без ожидания полного рефреша, а пользователь видит подтверждение в popup.

## Комментарии Work Item

- На карточке Work Item есть кнопка комментариев со счётчиком.
- Popup загружает комментарии через background-сообщение `get-comments`.
- Background вызывает Azure DevOps REST API `GET .../_apis/wit/workItems/{id}/comments`.
- При открытии панели комментариев список показывается под карточкой, а счётчик на кнопке обновляется по фактическому числу загруженных комментариев.
- После поиска по WI расширение отдельно подгружает счётчики комментариев для найденных задач.
- Новый комментарий отправляется из popup сообщением `add-comment`.
- Для совместимости со старым Azure DevOps Server запись выполняется через `PATCH .../_apis/wit/workitems/{id}` в поле `System.History`; после успешной записи комментарии перечитываются и UI обновляется.
- Текст комментария хранится как HTML-фрагмент: переводы строк перед отправкой заменяются на `<br>`.

## Списание времени в TimeSheet

- На карточке Work Item доступно действие списания времени в TimeSheet.
- В popup открывается меню с выбором даты и быстрыми вариантами от `0.5` до `8` часов.
- По умолчанию выбрана текущая дата; расширение находит неделю выбранной даты, при необходимости добавляет Work Item в TimeSheet и увеличивает значение за выбранный день.
- Запись сохраняется в TimeSheet с пустой `Activity`, чтобы не попадать в другие сценарии учёта.
- После успешной записи popup показывает подтверждение, при ошибке — текст ошибки.

## Структура проекта

- `manifest.json` — манифест MV3 и разрешения.
- `background.mjs` — обновления, badge, уведомления, обработка сообщений popup и content-script.
- `ado-api.mjs` — запросы к Azure DevOps API, маппинг WI, комментарии, создание задачи на ревью.
- `ado-config.mjs` — модель и загрузка конфигурации.
- `timesheet-api.mjs` — запись времени в TimeSheet.
- `options.html`, `options.css`, `options.mjs` — страница настроек.
- `popup.html`, `popup.css`, `popup.mjs` — UI popup и действия пользователя.
- `content-script.mjs`, `content-script.css` — кнопка **Design Review Task** на странице work item.
- `docs/documentation.md` — подробная техническая документация.
